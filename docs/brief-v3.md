# CodeKids implementation brief v3

Status: owner-approved on 7 November 2026. Source: Ahasanul Karim Khan's current request and Figma frame `Page 1 / 1:2`.

## Requirements Handshake

### Confirmed constraints

- [Brief] Build a polished, accessible and responsive executable landing page that follows the latest CodeKids Figma direction.
- [Brief] Plain HTML, CSS and JavaScript must run on GitHub Pages without a build step.
- [Brief] Parent-focused comparison precedes a trial request. The form needs default, validation-error and local-success states and must transmit nothing.
- [Brief] Desktop, tablet and mobile must avoid text squishing, orphan headings, clipping and horizontal overflow.
- [Brief] Source photography may not enter the public repository without verified redistribution rights.

### Open questions

- None blocks this portfolio prototype. Real provider operations, claims, asset licences and submission infrastructure remain outside scope.

### Assumptions carried forward

- [Inference][ASSUMED] English remains the prototype language because the supplied source frame and public case study are English. Owner approval is needed before a production localization scope.
- [Inference][ASSUMED] Google-hosted Fredoka and Nunito are acceptable for the public prototype; system fallbacks remain in CSS for blocked or slow font delivery.

## Mandatory six answers

1. **Who is it for, and who pays?** A parent or guardian compares courses and considers a trial. In a real service that adult would authorize spending; payment is outside this concept.
2. **What problem does it solve?** It helps the adult understand course options, age or level fit, learning outcomes and available evidence before requesting a trial.
3. **How will we know it worked?** The executable page matches the latest direction, the local form states work, and rendered audits pass at 1440, 834, 390, 360 and 320 px without critical layout defects.
4. **What cannot change?** Latest Figma direction, educational hierarchy, parent-focused copy, concept transparency, accessibility and responsive integrity.
5. **What are we not doing?** Backend, accounts, payment, production enrollment, database, real booking and any real form submission.
6. **Who approves?** Ahasanul Karim Khan.

## Emotional tone and direction

The page should feel encouraging to a child and dependable to an adult. Fredoka carries playful headings; Nunito keeps comparison and form content readable. The latest CodeKids Figma frame is the controlling visual reference.

## Success criteria

- Behavioral signal: a visitor can compare all three paths and complete the local trial-request demo with recoverable errors.
- Quality metric: all five required live viewports pass the six-point rendered audit with zero horizontal overflow and all interactive controls at least 44 px.
