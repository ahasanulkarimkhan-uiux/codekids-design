# Design decisions and evidence boundaries

## Purpose and contribution

CodeKids is Ahasanul Karim Khan's self-initiated Figma desktop landing-page concept. The design explores parent course comparison and trial requests. The designer's contribution is the page composition, course-comparison structure, trial-request interface and review-driven wording revisions.

## Course choice

Scratch, Python and web development are introduced as three course paths. Age ranges and example activities describe course fit. This comparison structure is a design choice; no parent interviews or observed comparison behavior are documented for this package.

## Trial request

The closing form uses persistent labels for parent name and phone or email. Revised copy explains that a callback confirms the time. A request therefore expresses interest rather than establishing a confirmed booking. The design does not demonstrate a functioning callback service.

## Page sequence and return routes

The page introduces the program, presents courses and invites a trial request. The revised footer includes program and trial routes. These describe the intended navigation; interactive links and submission behavior have not been implemented or tested here.

## Review history and limits

The latest local case-study revision identifies the work as a 1440 px desktop concept and records the callback wording and footer routes. Earlier reviews identified unsupported first-week wording and unverified social proof, as well as long-input clipping in a separate Figma stress copy. Do not treat those earlier claims as evidence or describe the form as validated.

The public preview selection excludes learner photography, project photographs, testimonials, sample pricing and full-page mockups with unresolved image permissions. It does not provide a rendered course-card comparison. The accompanying text explains that decision without claiming that a diagram is a screenshot of the interface.

No new Figma edits, redesign, website implementation, research, user testing or outcome measurement were performed for this GitHub package. The private Figma source is not distributed. No responsive or accessibility sign-off is claimed.

## Further verification if implementation is later commissioned

Long name/contact values, keyboard focus, field validation, empty and pending submission, failure recovery and confirmation would need verification in a working form. Responsive layouts would be a separate design scope. These are open implementation considerations, not completed work.
